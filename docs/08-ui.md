# 08 User interface

The interface is a desktop application window (Electron and React, ADR 0002), not a web page. It
should feel like a current native tool (in the spirit of VS Code, Linear or Figma's desktop app),
not like a website or a retro instrument panel.

## Principles

- **Modern desktop look.** Flat surfaces, one neutral grey scale plus one accent colour, 8 px
  spacing grid, 6 px corner radius, subtle borders instead of heavy boxes, the system font (Segoe UI
  Variable, SF Pro, Cantarell, Inter as fallback), tabular figures for every number. Light and dark
  themes follow the operating system; the waveform area stays dark in both. DLA_Logic's four trace
  colours (#e54242, #ff7f00, #007fff, #26ad34) are the default channel palette.
- **Native where it matters.** The operating system's own window frame and menu bar (no custom title
  bar), native open and save dialogs, file associations for `.lacap`, `.demo`, `.sr` and `.vcd`,
  drag a file onto the window to open it. Captures open as tabs in one window.
- **Command palette first.** `Ctrl+K` / `Cmd+K` searches every command (they all exist in the command
  API, ADR 0001), recent captures, channels, decoders and search hits. Everything has a keyboard
  shortcut, shown next to it.
- **Explain by default, stay out of the way when asked.** Every detection and problem has a "why";
  an "expert" toggle hides the explanations.
- **The person always sees what agents do, and can stop them.**
- **Calm motion.** Short transitions (120–200 ms) for panels and popovers only; nothing animates on
  the waveform except live capture. Respects the reduced-motion setting.
- Keyboard-operable everything, visible focus, sentence-case plain copy.

## Design system

- Tokens (colour, spacing, radius, type scale, elevation, motion) defined once in `packages/ui` as
  CSS custom properties, with a light and a dark set. Components use tokens only, never raw values.
- Components built on Radix UI primitives (menus, dialogs, popovers, tabs, tooltips, toggles),
  styled by us. No ready-made visual theme.
- Icons: one outline set at 16 and 20 px (Lucide).
- A component gallery (development builds only) shows every component in both themes, for checking
  by eye; axe checks run on it. No screenshot regression tests (flaky across fonts and systems).

├──────────────┴──────────────────────────────────────────────────────────────────┤                │
│ bottom panel (tabs): decoded table │ measurements │ activity                      │                │

- Sidebar, inspector and bottom panel are resizable, collapsible (`Ctrl+B`, `Ctrl+I`, `Ctrl+J`)
  and remember their size.
- Each tab has its own view (range, cursors, selection); the engine knows the views of all tabs and
  which tab is active, so agents can look at and move a specific one.
- Minimum window size 960 × 600. Below 1280 px width the inspector becomes an overlay drawer.
- A start screen when no capture is open: recent captures, connected devices, "open file", "try a
  demo capture" (synthetic device), and how to connect an agent.

## Screens and panels

- **Device panel:** found devices, connect, capabilities, setup help per operating system (doc 05),
  the output safety switch, who holds the lease and "take over from agent".
- **Capture bar:** rate and duration choices limited to what the device can do, with the reason
  when something is unavailable; trigger editor (edge or level per channel, pattern, protocol
  trigger built with the query builder for streaming devices).
- **Waveform:** LOD rendering (doc 04); zoom, pan, cursors snapping to edges, markers, range
  selection with live measurements; decoder rows with problem highlighting; live view while
  capturing (follows the newest data unless the person scrolls away). Trackpad pinch-zoom and
  two-finger pan.
- **Channel list:** rename, colour, hide, reorder by drag, group into buses, per-channel threshold
  where supported.
- **Analysis:** bus cards with detections and evidence, alternatives, what was ruled out and why,
  settings forms that re-decode instantly, problem explanations.
- **Decoders:** the decoder stack per bus, with layer decoders and register maps.
- **Search:** query builder with examples (it produces the JSON query of doc 06); hit list; next and
  previous hit.
- **Compare:** pick two captures, or paste expected bytes or text; differences listed and marked.
- **Decoded table:** virtualised list of packets and frames, filter, jump to the trace, send to the
  byte analyser, copy and export.
- **Activity feed:** every command with actor and time; agent commands highlighted. Any undoable
  entry has "undo" (ADR 0008); Ctrl+Z undoes the person's own last action. "Stop agent actions"
  pauses `capture` and `output` commands from agents. Output confirmations for agents appear as an
  in-app dialog, and as an OS notification when the window is in the background. "Started by an
  agent" is shown when `logica mcp` launched the app.
- **Agent pointer:** markers and view changes from an agent (`show_user`) appear with an "agent"
  badge and a short note, so "look here" works both ways.
- **Settings:** a settings window (theme, memory budget, capture folder, MCP on or off and port,
  connected agents, expert mode, updates).

## Performance budgets

| Interaction | Budget |
|---|---|
| App start to start screen (warm) | under 1.5 s |
| Pan and zoom, 16 channels, any capture size once indexed | 60 fps; no frame over 33 ms |
| Open a 1e9-sample, 16-channel `.lacap` (already indexed) | first view under 2 s |
| Import and index a 50 M-sample, 6-channel `.demo` | under 2 s on a laptop |
| Change a decoder setting, visible window updated | under 100 ms |
| Renderer main-thread task during capture or import | none over 50 ms |

Checked on the owner's reference machine at every milestone exit, with Playwright traces; results
go to `docs/benchmarks.md`. CI records the same traces but fails only on regressions of more than
2× the baseline (doc 10). If Canvas 2D cannot meet the pan and zoom budget at 32 channels, the trace
layer moves to WebGL2 (recorded as an ADR then).

## Accessibility

- The waveform is a canvas; everything on it is also available as text: measurements, decoded
  table, search hits, markers. The canvas has a live text description of the visible range.
- The keyboard map is documented in the app (`?` and the command palette) and follows Signal
  Detective's.
- Colour is never the only signal: problems also have shapes and text; trace labels name channels.
- Contrast meets WCAG AA in both themes (checked on the token set); axe checks in the Playwright
  tests.
